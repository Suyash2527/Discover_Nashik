# Discover Nashik — AI Execution Plan
**Split across Antigravity + Claude Code · 24-hour build · ₹0 stack**

---

## 0. The Core Rule: Split by Folder, Not by Feature

Two AI agents editing the same files at the same time will overwrite each other's work. Give each agent its **own folders**, and have them connect only through **shared contracts** (types + JSON schema) that you lock at H0.

| Agent | Strengths we use | Owns |
|---|---|---|
| **Antigravity** (Gemini, built-in browser, Agent Manager for parallel agents) | UI, visual iteration, testing in its own browser, Google stack (Firebase, Gemini) | `app/(ui)/`, `components/`, `styles/`, Firebase console setup, browser testing |
| **Claude Code** (terminal, strong at multi-file logic and refactors) | Voice pipeline, RAG, service worker, data validation, API routes | `lib/`, `app/api/`, `public/sw.js`, `data/`, `scripts/` |
| **Humans** | Collecting verified places, API keys, Twilio KYC, pitch | `data/places.raw.csv`, `.env.local`, the pitch |

**Shared (locked at H0; change only by team agreement):** `types/`, `data/schema.json`, `CONTEXT.md`.

## 2. Shared Contracts (write these at H0, before any agent runs)

### `types/place.ts`
```ts
export type Category =
  | "temple" | "ghat" | "stay" | "food" | "parking"
  | "hospital" | "police" | "toilet" | "water" | "chemist";

export interface Place {
  id: string;                 // "kalaram-mandir"
  name: { en: string; hi: string; mr: string };
  aliases: string[];          // STT variants: "kala ram", "काळाराम"
  category: Category;
  lat: number; lng: number;
  area: "Panchavati" | "Nashik Road" | "Trimbakeshwar" | "Tapovan" | "City" | string;
  description: { en: string; hi: string; mr: string }; // 1–2 sentences
  timings?: string;           // "05:00–21:00"
  phone?: string;
  open24x7?: boolean;
  accessible?: boolean;       // elderly / wheelchair friendly
  verified: { by: string; on: string; source: string }; // person, date, how checked
}
```

### `types/advisory.ts`
```ts
export interface Advisory {
  id: string;
  placeId?: string;           // advisory attached to a pin
  message: { en: string; hi: string; mr: string };
  severity: "info" | "warning" | "closed";
  startsAt: string; endsAt: string;  // ISO
  createdBy: string;
}
```

### `types/voice.ts`
```ts
export type Lang = "en-IN" | "hi-IN" | "mr-IN";
export interface AskRequest  { query: string; lang: Lang; lat?: number; lng?: number }
export interface AskResponse {
  answer: string;             // max 2 sentences
  placeIds: string[];         // UI highlights these pins
  source: "gemini" | "offline";
}
```

### Firestore
- `advisories/{id}` → `Advisory` (public read; write only for admin emails)
- Places stay in **static JSON** (faster, works offline, and uses no Firestore quota)

## 4. Git Workflow

- `main` is protected, and Vercel auto-deploys from it.
- Antigravity works on `feat/ui-*` branches, and Claude Code works on `feat/core-*` branches.
- **The integration lead** (one human) merges at every checkpoint: **H6, H12, H16, H19**.
- Run both tools in separate clones or git worktrees (`git worktree add ../dn-core feat/core`) so they never share a working directory.

> **Claude Code prompt (H2):**

Call Gemini with only the retrieved places as context; instruct it to answer in the request language in at most 2 sentences and never invent places. Add a 2.5 s timeout that falls back to lib/intent-offline.ts. Write unit tests for rag.ts with 10 queries including 'Ramkund', 'Trimbak', 'nearest hospital', 'जवळचे हॉस्पिटल'."

### H6–12 · Voice Loop End-to-End *(Claude Code leads)* ‖ UI polish *(Antigravity)*

**Claude Code** — *prove ONE spoken answer before any polish*
- `lib/stt.ts`: Web Speech `SpeechRecognition` with `lang` set to mr-IN/hi-IN/en-IN; after transcription, run **alias correction** (map mishears → Trimbakeshwar, Ramkund, Panchavati, Tapovan, Kalaram)
- `lib/tts.ts`: `speechSynthesis` using the best matching voice; fall back to Sarvam TTS when no voice exists for `mr-IN`
- `lib/intent-offline.ts`: template answers for when there's no network ("The nearest hospital is X, about Y km away.") in all 3 languages
- Expose one hook, `useVoiceAssistant()` → `{ start, stop, state, transcript, answer, placeIds }`

**Antigravity**
- `VoiceButton.tsx`: a large mic FAB that consumes `useVoiceAssistant()` and shows listening / thinking / speaking states and a live transcript
- When `placeIds` come back, fly the map to those pins and pulse them
- `LangToggle` + `lib/i18n` (all UI strings in en/hi/mr)

> **Handoff contract:** Claude publishes the `useVoiceAssistant` signature in `lib/voice/index.ts` **by H7** with a mocked implementation, so Antigravity can build against it immediately.

**✅ Checkpoint H12 (merge):** Speak Marathi → hear a Marathi answer → the map flies to the pin. **Record this on a phone right away as an early backup clip.**

## 7. Prompting Rules for Both Agents

1. **Contracts first:** start every session with "Read CONTEXT.md and /types."
2. **One feature per prompt:** give it a clear definition of done ("send a screenshot", "tests pass").
3. **Ask for a plan before code** on anything bigger than one file (Claude Code: plan mode; Antigravity: planning mode).
4. **Never let an agent edit `/types`**. If it asks to, a human decides.
5. **Review the diff before merging.** Both tools can quietly add dependencies, so check `package.json` changes.
6. **When stuck for 20 minutes**, hand the problem to the *other* agent with the error log.
